# 외부 채점 — 사용 안내

평가기는 학습자가 실행하는 도구다. 모델을 호출하거나 수정 루프를 자동 실행하지 않는다.
자동 과제 실행·모델 비용 집계는 Day 6 이후 하네스에 붙일 수 있다.

## 과제

`tasks.json`의 task-01~04는 개발용, task-05~06은 마지막 확인용이다.
작업 실패·중단 복구는 Go 기능 과제와 별개로 Day 4·5·9에서 시험한다.
이 구분은 최초 제안의 예시를 실제 채점 가능한 과제로 구체화한 것이다.
매 과제는 **동일한 최초 fixture에서 독립적으로** 시작하며 앞 과제의 수정에 의존하지 않는다.

```bash
mkdir -p workspaces
cp -R fixtures/go-service workspaces/task-01
# task-01 prompt를 직접 만든 에이전트에 전달해 수정한다.
docker pull golang:1.23-bookworm
python3 -m evals.grade --candidate workspaces/task-01 --task task-01
```

현재 fixture는 의도적으로 문제를 포함하므로 외부 과제 테스트가 실패하는 것이 정상이다.
`go test ./...`의 기본 스모크 테스트는 정상 응답만 확인한다.

## 채점 경계

- 에이전트에는 `workspaces/task-NN`만 제공한다. 전체 저장소나 evals를 마운트하지 않는다.
- 채점기는 candidate의 최상위 `.go` 소스만 복사하고 candidate 테스트·go.mod는 사용하지 않는다.
- 외부 baseline 테스트와 선택한 과제 테스트를 별도 컨테이너에서 실행한다.
- 표준 라이브러리만 허용한다. 후보 코드의 다운로드·호스트 실행은 하지 않는다.
- symlink와 대용량 파일을 거절하고 컨테이너 시간·자원·출력을 제한한다.
- `grader_error`는 에이전트 실패로 점수화하지 않는다. Docker 설치·이미지·환경을 먼저 확인한다.
- 이 환경 제한은 학습용이며 악성 코드에 대한 완전한 보안 격리를 보장하지 않는다.

## 최종 확인 과제

task-05~06도 저장소 안에 공개되어 있으므로 보안상 숨겨진 테스트가 아니다.
개발 중 읽지 않겠다는 학습 규칙과 작업 마운트 분리로 튜닝 오염을 줄인다.
평가한 뒤 수정에 사용했다면 더 이상 미사용 확인 과제가 아니라고 기록한다.

## 채점 범위의 한계

함수 추출 과제는 health.go의 함수 선언과 service.go의 참조, 응답 동작을 검사한다.
그것만으로 코드 품질 전체를 판정하지는 않는다. AST 정교화나 사람 리뷰는 후속 확장이다.
과제 통과 시 다른 정상 endpoint도 baseline 테스트로 확인하지만 모든 회귀를 검출하지는 않는다.
비용·토큰은 모델 호출 하네스가 기록하고 채점기는 실제 코드 동작만 기록한다.
