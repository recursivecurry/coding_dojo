# 흔한 실패와 조사 순서

| 현상 | 먼저 확인 | 개선 실험 |
|---|---|---|
| 같은 파일을 계속 읽음 | 도구 결과가 history에 들어갔는지 | 중복 호출 표시·검색 결과 개선 |
| 편집 성공인데 테스트 실패 | 실제 변경 diff와 실행 cwd | 경로 명시·실행 결과 구조화 |
| tool call 오류 반복 | Schema, arguments, ID 대응 | 인자 검증 오류를 구체적으로 반환 |
| 끝없이 수정 | 종료 조건·턴 제한·재시도 범위 | 반복 실패 중단과 체크포인트 |
| 컨텍스트 증가 | 도구 출력 크기·전체 파일 반복 | 부분 읽기·절단·선택적 로딩 |
| 재개 시 수정 중복 | pending action·파일 해시 | 완료 여부 확인 후 재실행 |
| 리뷰어가 무조건 칭찬 | 작성자의 서술만 전달했는지 | diff와 요구사항·실행 증거 제공 |
| 테스트만 지워서 통과 | 채점 코드 위치 | 외부 테스트로 채점 |
| SDK 예제가 동작 안 함 | 문서 버전·설치 SDK·모델 지원 | 버전 기록 후 공식 예제로 최소 재현 |

실패를 모델 능력으로 단정하기 전에 도구·환경·피드백 누락을 확인한다.
한 번 성공한 사례만으로 개선을 확정하지 말고 같은 초기 상태에서 반복한다.
