# 도구 계약

| 도구 | 입력 | 결과와 제한 |
|---|---|---|
| `list_files` | `{}` | 허용 확장자만, 숨김 파일 제외, 최대 200개; 초과 여부 표시 |
| `read_file` | `path: str` | UTF-8 텍스트 최대 12,000자, 절단 표시 |
| `search` (Day 3) | `query`, 선택 `path` | 파일·줄 번호·일치 부분; 결과 건수 제한 |
| `apply_patch` (Day 3) | `path`, `old`, `new` | 기존 텍스트가 정확히 1회 일치해야 수정; 충돌 시 오류 |
| `run_command` (Day 4~5) | `argv: list[str]` | exit code, bounded stdout/stderr, timeout, 실행 시간 |
| `load_skill` (Day 10) | `name` | 허용된 지침 본문; 경로를 모델이 임의 지정하지 않음 |

시작 코드의 도구는 앞의 2개뿐이다. 뒤의 계약을 하루별로 구현한다.
모든 쓰기는 root.resolve() 기준 경로 검증을 적용한다. symlink 탈출, 절대 경로, `..`를 검사한다.
이 검증은 동시 공격에 대한 완전한 파일시스템 격리가 아니다. 실행 영역은 전용 복제본으로 제한한다.

오류 결과는 `{"ok": false, "error": "..."}` 형태로 모델에 반환한다.
알 수 없는 도구·잘못된 인자는 실행하지 않는다. 공급자 오류와 도구 오류를 섞지 않는다.
명령은 호스트 셸로 넘기지 않는다. 고정된 Docker 실행 명령을 하네스가 구성하고, 컨테이너 안에서만 실행한다.
출력은 메모리에 무제한 쌓은 다음 자르지 말고 읽는 시점부터 제한한다.

Day 3 패치는 간단한 정확 일치 방식으로 충분하다. 전체 unified diff 파서 구현은 범위 밖이다.
