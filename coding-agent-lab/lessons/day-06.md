# Day 06 — 평가 기반 만들기

시간: 150분. 이전 일차 결과를 사용하며, 하루가 끝나면 완료 조건과 미완료 항목을 기록한다.

## 핵심 개념

trace는 실행 과정이고 outcome은 최종 상태다. 좋은 평가에는 고정된 초기 환경과 독립적인 채점 기준이 필요하다.

## 실습 순서

1. **25분:** evals/README와 공식 eval 가이드의 task/trial/grader/outcome 정의를 읽는다.
2. **55분:** 과제 1~4를 각각 새 작업 복제본에서 실행하고 외부 Docker 채점기로 검사한다.
3. **45분:** metrics.csv에 모델·소스 해시·설정·성공·시간·토큰을 기록한다. 실패 원인을 분류한다.
4. **25분:** 같은 과제 하나를 반복하고 결과 변동을 기록한다. 자동 평가 루프는 선택적으로 구현한다.

## 완료 조건

- [ ] 과제별 초기 상태를 동일하게 재생성
- [ ] 에이전트 작업 영역과 채점 코드를 분리
- [ ] 최소 4개 개발 과제의 기준 결과 확보

## 실패 실험

작업 복제본의 테스트를 삭제해도 외부 채점 결과가 바뀌지 않는지 확인한다.
