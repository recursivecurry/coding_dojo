# Day 04 — 테스트 피드백과 자기 수정

시간: 120분. 이전 일차 결과를 사용하며, 하루가 끝나면 완료 조건과 미완료 항목을 기록한다.

## 핵심 개념

모델의 자신감보다 실행 결과가 강한 피드백이다. 실패를 관측하고 다음 행동에 반영하는 것이 단순 코드 생성과의 차이다.

## 실습 순서

1. **20분:** exit code·stdout·stderr·timeout·duration 결과 형식을 정의한다.
2. **50분:** 처음에는 모의 실행기로 실패→성공 결과를 반환하고 run_command 피드백 루프를 구현한다.
3. **30분:** Docker 사용이 가능하면 고정된 go test 실행만 연결한다. 임의 명령 실행은 Day 5 정책 이후 활성화한다.
4. **20분:** 틀린 수정을 한 번 유도해 재수정 trace를 남긴다.

## 완료 조건

- [ ] 실패 exit code와 stderr를 다음 모델 호출에 전달
- [ ] 명령 완료와 테스트 통과를 구분
- [ ] 실패→수정→검증 순서의 증거 확보

## 실패 실험

테스트 출력에서 핵심 에러를 제거한 경우와 보존한 경우의 행동 차이를 관찰한다.
