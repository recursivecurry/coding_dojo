# 코딩 에이전트 직접 만들기 — 2주 / 30시간

2026-11-01 기준 학습 설계. Python으로 하네스를 구현하고, 작은 Go HTTP 서비스를 수정한다.
목표는 모델 교체가 아니라 도구·컨텍스트·검증·복구가 결과에 미치는 영향을 설명하는 것이다.

## 바로 시작

```bash
git clone --branch learning/coding-agent-lab-20261101 https://github.com/recursivecurry/coding_dojo.git
cd coding_dojo/coding-agent-lab
python3 --version  # 3.11 이상
python3 -m unittest discover -s tests -v
python3 -m starter.cli --repo fixtures/go-service --task "서비스 파일을 조사하라"
```

마지막 명령은 API 키 없이 작동하는 **스크립트 기반 시뮬레이터**다. 실제 LLM이 판단하거나 코드를 고치지 않는다.
실제 모델 연결과 편집·명령 실행은 실습에서 구현한다. 완성 답안을 복사하는 대신 동작 계약과 체크리스트를 제공한다.

1. [사전 준비](docs/setup.md)를 확인한다. 설치 시간은 별도이며, 첫날 환경 진단은 수업에 포함한다.
2. [전체 일정](docs/curriculum.md)에서 오늘의 가이드를 연다.
3. [Day 1](lessons/day-01.md)을 진행한다.
4. 하루가 끝나면 [학습 기록](templates/daily-log.md)을 복사하고 코드와 함께 커밋한다.

## 구성

| 경로 | 내용 |
|---|---|
| `lessons/day-01.md` ~ `day-14.md` | 핵심 개념, 분 단위 실습, 완료 조건, 실패 실험, 회고 질문 |
| `starter/` | 표준 라이브러리만 쓰는 읽기 전용 최소 하네스와 CLI |
| `fixtures/go-service/` | 의도적인 버그가 있는 Go 실습 대상과 정상 동작 스모크 테스트 |
| `evals/` | 4개 개발 과제, 2개 최종 확인 과제, 외부 Go 채점 테스트와 Docker 채점기 |
| `docs/` | 아키텍처, 도구 계약, 모델 연결, 확장 실험, 자료 출처, 문제 해결 |
| `templates/` | 일일 기록, 실행 지표 CSV, 실험·인계·최종 회고 양식 |
| `tests/` | 최소 하네스와 평가 도구의 자동 검증 |

## 30시간의 범위

직접 구현: 모델/도구 루프, 검색·편집·검증, 기본 격리, 로그·평가, 컨텍스트 선택, 체크포인트.
작은 실험: Skills식 지침 로딩, MCP 도구 1개, 작성자/리뷰어 분리, 고급 도구 사용 1종.
후속 과정: 파인튜닝·강화학습, 대규모 RAG/LSP, IDE·웹 UI, PR 자동화, 대규모 멀티 에이전트, 운영 수준 보안.

Day 7까지 수정→테스트 루프가 불안정하면 Day 12~13을 복구 시간으로 사용한다.
이때 심화 실험은 미완료로 기록하며 30시간 안에 모두 끝냈다고 표시하지 않는다.

## 비용과 결과 해석

API 호출은 선택한 공급자의 별도 과금 대상일 수 있다. 실제 가격은 공급자 공식 페이지에서 확인한다.
첫 실험 전 대시보드 사용 한도와 로컬 턴·출력 토큰 상한을 설정한다. 이 저장소는 API를 자동 호출하지 않는다.
6개 과제는 학습용 회귀 평가이며 공개 벤치마크 성능이나 일반적인 코딩 능력을 입증하지 않는다.

검증 현황과 실행 제약은 [VALIDATION.md](VALIDATION.md)에 기록한다.
